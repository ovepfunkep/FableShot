# Данные, MyTargets и перенос дневника

Рабочая спецификация 0.2. Подтверждены локальная работа и импорт MyTargets. Детали восстановления и схемы предложены для разработки; финальные сериализованные форматы необходимо закрепить до написания соответствующей функции.

F01: конкретизированы [контракт ядра/расширений](architecture/data-contract.md) и [переход со схемы 1](architecture/migrations.md). Текущее дисковое хранение и восстановление после остановки процесса проверены изолированно; новая схема ещё не установлена. При реализации использовать эти документы вместе с требованиями импорта ниже.

## Локальная модель

- **Session**: локальный UUID, название, состояние, исходная календарная дата, доступные временные данные, заметки и источник.
- **Block**: порядок в тренировке, дистанция, снимок геометрии/профиля мишени с версией, снимок выбранного снаряжения.
- **End**: порядок в блоке, плановое количество стрел, разминка/зачёт, доступное время серии и признак неполноты.
- **Shot**: UUID, серия, порядковый номер ввода, итоговые очки, M/X, необязательные координаты, качество/происхождение позиции и результата, необязательный номер физической стрелы.
- **UnscoredCount**: блок/серия и количество неоценённых выстрелов. Это не набор Shot с нулевыми очками.
- **Bow / ArrowSet / Setup**: текущие карточки снаряжения, признак архива. Настройки, использованные в блоках, сохраняются снимками.
- **Note / Attachment / PhotoCalibration**: собственные записи и вложения, привязки к сущностям, параметры ручной разметки.
- **TechniqueGuide / GuideVersion / Focus / Reflection**: памятки, неизменяемые опубликованные редакции, фокусы и наблюдения. Сессия ссылается на конкретную редакцию.
- **Goal / Achievement**: отдельные правила и вычисленное состояние; отключение показа не удаляет первичные результаты.
- **ImportBatch / ImportedGroup**: происхождение файла, распознанные группы, принятые решения пользователя, созданные объекты и данные для защиты от повторного переноса.
- **Settings**: оформление, поведение ввода, звук/вибрация, видимость мотивационных блоков и памятки. Хранить отдельно от истории попаданий.
- **LocalProfile**: отображаемое имя, необязательные фото/клуб/описание/реальная дата начала занятий и настройка видимых полок. Это один локальный пользователь, без онлайн-аккаунта.
- **Групповая комната:** участники, собственная зачётная запись, подтверждённые редакции серий, исходящие операции и снимок общего итога отделены от личного дневника. [Модель и права](group-session.md). Чужой результат не создаёт стрелы в своей истории; собственный результат не дублируется после переподключения.
- **Турнирное участие**: подтверждено отдельное хранение факта события, результата и места без обязательных стрел. Выбран T1: Tournament и собственные TournamentEntry с привязкой Session; [принятое поведение](resolved/tournaments/README.md). Итог протокола не заменяет первичные очки стрел.

Даты и время — типизированные значения. Часовой пояс не приписывается CSV, если его там нет. У собственных новых тренировок фиксируются момент начала, зона и календарная дата на устройстве. У импортированных данных явно различать время серии, дату занятия и время импорта.

Координаты nullable; пара `(0,0)` допустима для реального центра. Промах, неоценённый выстрел и неизвестное значение — разные состояния. Итоговые суммы рассчитываются по данным стрел, не по форматированным строкам.

## Защита истории

- Изменение карточки лука/стрел не переписывает старые условия. Изменение профиля мишени создаёт новую версию, а прошлые записи используют старую.
- Сохранение серии, завершение занятия и импортированные порции выполняются транзакционно. Миграции БД не используют разрушительную замену при ошибке.
- Корзина исключает записи из аналитики. Восстановление возвращает связи и пересчитывает производные показатели.
- Данные находятся в закрытом хранилище Android. Для первой концепции нет рекламного, аналитического или удалённого crash SDK.
- Системный облачный автоперенос истории не является неявной частью обещания «всё на телефоне». Рабочее решение — исключить данные дневника из автоматической облачной копии Android; собственный перенос выполняется явным экспортом/восстановлением.
- При входе в групповую комнату явно разделять локальную личную историю и публикуемые данные текущей сессии. Возможный сервер хранит только необходимые данные комнаты по согласованной политике; фото, личные заметки и шпаргалки автоматически не загружаются. Это не полная облачная синхронизация дневника.

## Контракт импорта MyTargets

Исследован пример пользователя с 15 столбцами, разделителем `;`, 18 строками стрел. Сводка и путь источника находятся в [решениях](decisions.md).

### Чтение

- Системный выбор файла, локальная потоковая обработка без загрузки на сервер.
- CSV-парсер поддерживает кавычки, экранированные кавычки, переносы внутри полей и UTF-8 с BOM/без BOM. Разбор через простое разделение строки по `;` недопустим.
- Распознавать формат по заголовкам, не по имени файла. Перестановка известных столбцов допустима; неизвестные дополнительные поля сохранять в сведениях источника по возможности.
- Для неподдержанного кодирования или повреждённого CSV показать причину и место ошибки. Не подменять нечитаемые значения нулями.
- Рабочий защитный предел: 25 МБ CSV и 250 000 строк стрел, с понятным сообщением при превышении. Это инженерные пределы для проверки на реальных файлах, не ограничение числа тренировок в дневнике.

### Группировка и предпросмотр

- `Title`, `Date`, `Standard round` помогают определить тренировку; `Round`, `Distance`, `Target`, `Bow`, `Arrow` — блок; `End` и `Timestamp` — серию. Это признаки, а не гарантированные внешние идентификаторы.
- Следовать порядку файла, учитывать сбросы номеров и смены внешних полей. Изменение лука само по себе не доказывает начало другой тренировки.
- Для неоднозначных одинаково названных занятий одного дня предложить границы групп в предпросмотре. Пользователь может разделить/объединить предложенные группы до записи. Не объединять всё только по названию и дате.
- Предпросмотр содержит дату, условия, количество блоков/серий/стрел, сумму, миниатюру координат и все предупреждения. Можно выбрать только часть тренировок.
- Отдельно показывать нерешённые профили мишеней, неизвестный смысл координат, ошибки значений и предполагаемые повторы. Сохранение выбранных групп доступно после разрешения блокирующих неоднозначностей.

### Очки и позиции

- `M` → промах, 0 очков; `X` → 10 и X; разрешённые числовые значения → исходные очки. Неизвестный символ требует разбирательства, а не автоматического M.
- Очки источника остаются окончательными. Пересчёт по координатам — только проверка и явное действие пользователя, не обязательный шаг переноса.
- Для M с `(0,0)` из исследованного профиля MyTargets считать координаты отсутствующими. Для обычного попадания `(0,0)` сохраняет реальный центр.
- Пустые координаты остаются отсутствующими. Пары с NaN/Infinity и неполные пары не попадают в геометрию; показывается предупреждение.
- Время, одинаковое для всей серии, хранить как время серии. Не вычислять физическую последовательность выстрелов и длительность занятия по времени ручного ввода.
- Размер/дистанцию разбирать с явными единицами. Неизвестную единицу или профиль оставить для уточнения; исходную строку сохранять.
- Название `WA Full (60cm)` помогает распознать лицо, но не доказывает полные правила конкретного спортивного формата. Сопоставление профилей версионируется и проверяется отдельно.
- Масштаб и направление осей MyTargets должны быть подтверждены по формату/сопоставлению реальной мишени до включения импортированных позиций в обычную пространственную аналитику. Пока ориентация не подтверждена, очки можно перенести, сырые координаты сохранить как неподтверждённые.

### Повторы и сохранение

- Считать SHA-256 файла и хранить, какие подтверждённые группы уже перенесены. Повторный выбор того же файла с другим именем не дублирует ранее выбранные группы и позволяет перенести ещё не выбранные.
- Дополнительно вычислять отпечаток содержимого подтверждённой группы, сохраняя кратность одинаковых строк. Возможные совпадения между разными экспортами показываются пользователю; не объявлять их одним занятием без достаточных оснований.
- Строка источника имеет свою позицию и идентичность внутри группы. Три одинаковых M — три стрелы, не одна.
- Результат импорта — одна атомарная порция выбранных групп. Отмена/ошибка до записи не оставляет половину тренировки. Блокирующая ошибка не скрывается как «успешно пропущенная» строка.
- Допускается перенос исправной части только после явного выбора пользователем групп/серий и показа, что не будет перенесено. Неполнота не маскируется промахами.
- После записи показать перенесённые/пропущенные группы и переход в Историю. Старые достижения не разворачиваются во всплывающий парад уведомлений.
- Отмена порции удаляет созданные ею тренировки. Если пользователь уже редактировал связанные объекты после импорта, сначала показать затрагиваемые изменения; общие объекты снаряжения не удалять, пока на них ссылаются другие занятия.

## Архив и восстановление

Предлагаемый формат: ZIP с manifest, версионированными JSON-данными и вложениями по относительным идентификаторам. Manifest содержит версию формата, дату, количество сущностей и контрольные суммы файлов. Ключ подписи APK и любые секреты разработки в архив не входят.

- Сериализация сохраняет UUID, снимки условий, версии памяток, источник, исходные импортные значения и настройки. PDF и картинка не заменяют архив.
- Экспорт выполняется из согласованного снимка БД; параллельная правка не должна создавать архив с половиной старых и половиной новых связей.
- Выбор папки через системный диалог, для отправки — системное меню. Успешной считается завершённая запись; отмена диалога не обновляет дату последней копии.
- Восстановление сначала проверяет версию, контрольные суммы и связи во временном хранилище. Более новый неизвестный формат не заменяет текущие данные.
- Пути ZIP проверять на выход из каталога; ограничить суммарный распакованный размер и число файлов. Рабочие пределы — 1 ГБ и 20 000 файлов; архив без фото должен оставаться возможным для больших дневников.
- Перед полной заменой показывать состав обоих дневников и возможность сохранить текущий. Замена происходит атомарно после явного подтверждения. При неудаче текущий дневник остаётся доступен.
- Полное слияние двух независимых архивов — отдельное расширение. Первый контракт восстановления использует замену, а импорт MyTargets добавляет историю.
- Архив содержит личные записи и фото в обычном переносимом формате; шифрование экспортируемого архива не заявлено. Опциональный защищённый архив требует отдельного решения.

## Проверки

- Пример пользователя: одна тренировка, 6 серий, 18 стрел, 99 очков; три одинаковых M сохранены, ложных центральных точек нет.
- UTF-8 BOM, переставленные столбцы, `;` и перенос строки внутри кавычек, пустые поля снаряжения.
- Повтор файла/переименование; частичный выбор, затем импорт оставшихся групп; пересекающиеся экспорты разного состава.
- Несколько тренировок с одинаковым именем и датой, несколько дистанций в одной, неизвестный профиль и повреждённая строка.
- Сбой/отмена посередине не оставляет частичных записей. Ошибка архива и несовместимая версия не повреждают текущий дневник.
- Полный цикл «запись → архив → чистая установка → восстановление» сохраняет результаты, версии техники, фото, настройки и источники.


## Расширение данных 0.5

Для точного ввода разделять сохранённые нормализованные координаты Shot и состояние вида мишени: активные block/face, масштаб и смещение полотна. Черновик наведения/положение пальца/пиксели лупы не являются Shot и не создают статистику до подтверждения. Лупа и зум используют то же обратное преобразование экран → координаты лица; изменение масштаба не переписывает попадания. Эти поля/операции конкретизируются в следующем контракте данных.

[Контракт метрик и отчётов](metrics-and-reports.md) обязателен для проектирования схемы: сохранять первичные факты и происхождение, а не только экранные итоги.

- MetricDefinition и MetricValue: ID/версия формулы, единицы, область, исходная редакция, охват, значение либо причина отсутствия. Производные значения пересчитываемы; произвольные комбинации фильтров не материализуются бесконечно.
- BaselineSnapshot и ComparisonSnapshot: политика похожести, список прошлых тренировок/редакций, агрегаты и изменения. База текущего занятия не включает само занятие.
- ScoringDefinition и ScoreBreakdown: общая версия правил/весов, компоненты и их доступность. [Оценивание](scoring-and-progress.md).
- MetricEvent / AchievementRule / AchievementGrant: версия критерия, основание/источник, устойчивый ключ выдачи и причина пересмотра. Расчёт факта не равен показу анимации.
- GroupRoom / RoomMembership / GroupEntry / SharedEndRevision: собственные права, независимые серии, опубликованные редакции и версии условий.
- GroupHistorySnapshot: полученные результаты по сериям для восстановления срезов, время обновления, ссылка на собственную Session без копирования стрел.
- LocalDeletionMarker: удаление локальной истории не возрождается при следующем фоновом обмене и не удаляет данные у других.
- OutboxItem: устойчивые ID операций, состояние подтверждения сетевым узлом, повтор/редакция без двойного начисления.

Перечень полей исходных данных, недоступные метрики, версии пересчёта и правила хранения снимков описаны в отдельном контракте. В архив входят применимые первичные данные, определения и исторические снимки; активные токены/секреты приглашений исключаются. Снимки не заменяют исходные координаты/очки.

Для первого локального сетевого прототипа устойчивое хранилище узла — на телефоне. Срок облачного хранения не ограничивает локальную историю. Удаление у себя, выход из участия и удаление вклада у других не объединяются одной операцией. Изменения схемы требуют миграций без потери исходных результатов.

Рабочее хранилище локальной комнаты и личная запись истории узла имеют раздельный жизненный цикл: удаление собственной истории не каскадирует в SharedEndRevision остальных. Остановка сетевого узла — явное отдельное действие, сохранённые копии у других не затрагиваются.

CG3 хранит профиль/версию, k и фазу, S/N/H, внутрисерийные r_j², Q/D/T, компоненты и причины недоступности. [Принятые формулы](resolved/general-scoring/README.md). Полные координаты для расчёта стандартного CG3 принимает сервис узла; рядовым клиентам по умолчанию передаются проверенные агрегаты, а не чужие мишени. Такие сервисные данные не становятся собственными Shot пользователя узла и не включаются в его обычный личный экспорт как его стрельба.
