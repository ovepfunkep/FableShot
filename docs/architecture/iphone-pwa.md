# FableShot через Safari и в Android APK

11 ноября 2026 года Иван исключил App Store из-за стоимости членства в Apple Developer Program. Для iPhone первый кандидат — PWA, которую открывают по HTTPS и добавляют на главный экран из Safari. Текущий Android-клиент выпускается как APK. [Инструкция Apple](https://support.apple.com/ru-ru/guide/iphone/iphea86e5236/ios)

## Как организовать перенос

[План переноса и статус каждого пакета](web-migration-plan.md)

Предложение для проверки — один репозиторий и новый каталог `web/` для общего интерфейса React. Текущий `android/` продолжает собирать APK на Kotlin. На этапе прототипа один веб-код выпускается в двух вариантах. Для Safari это статическая PWA на GitHub Pages. Для Android Capacitor упаковывает те же файлы в тестовый APK. Отдельную оболочку Capacitor можно разместить в `web/android/`. [Упаковка приложения через Capacitor](https://capacitorjs.com/docs/getting-started)

Перед переносом сохранить отдельную точку в Git после проверки текущего пакета. У текущих доработок 0.30.2 есть локальные изменения, первый коммит репозитория их не содержит. Точка Git нужна для исходников, резервная копия дневника нужна для данных телефона. Они проверяются отдельно.

При веб-задаче читать `web/`, нужный контракт и тестовые примеры. Старые Android-исходники читать по конкретному экрану или поведению, которое переносим. В рабочей очереди хранить ближайший сценарий и его проверку. Общие требования, оформление и примеры держать в одном месте.

Иван подтвердил цель переноса: функциональность и внешний вид совпадают с действующим Android. Для каждого перенесённого сценария сверять экран, состояния, подписи, жесты, расчёты и сохранение. Эталон — рабочий Android-код и последние решения пользователя. Платформенные возможности Android подключать в APK и отдельно проверять доступный аналог для Safari. Промежуточный выпуск показывает, какие части уже перенесены. [Текущий этап](../work-queue.md)

### Прямой перенос Compose-компонентов

Для каждого экрана держать рядом исходный Compose-компонент и его React-аналог. Последовательно переносить дерево элементов, параметры оформления, состояния и обработчики. Сохранять порядок, подписи, размеры, отступы, шрифты, цвета, радиусы, доступность и условия видимости. Числа и строки брать из исходников и подключённой темы. Сначала переносить используемые повторно элементы, например поле условий, плитку результата и полосу стрел.

`Column` соответствует вертикальному flex-контейнеру, `Row` — горизонтальному. У `Box` переносить взаимное расположение слоёв, у `Modifier` — итоговые размеры, область нажатия и порядок отступов. Значения `dp` служат ориентиром CSS-пикселей при стандартном масштабе. Для текста переносить размер, высоту строки, вес и межбуквенный интервал Manrope. Полученную компоновку проверять снимками одного размера с одинаковыми данными.

Состояния и команды переводить по существующим переходам Android. Сначала составить соответствия используемых API. Для Room, системных файлов, жизненного цикла и Android-жестов подключить нужную реализацию веба или Capacitor и проверить прежний контракт. Различия платформ фиксировать в очереди для конкретного сценария. Проверки совпадения расчётов и сохранённых данных остаются обязательными при изменении этих частей.

Пример — таймер, перенесённый из `android/app/src/main/java/app/fableshot/android/ui/PracticeTimerWindow.kt` и `PracticeTimer.kt`. Сверены быстрые значения, настройки периода и отдыха, команды запуска, паузы и сброса, видимый отсчёт и анимация изменившихся цифр. Проверка после сворачивания опирается на сохранённое время окончания.

## Первый прототип

Проверить один сценарий на iPhone и в отдельной Android-сборке с искусственным дневником. На iPhone после первого открытия и добавления на главный экран включить авиарежим. На обоих телефонах отметить три стрелы на мишени, проверить лупу и зум, сохранить серию. Закрыть приложение, открыть с иконки без интернета и проверить сохранённые попадания и сумму.

Для проверки достаточно одной мишени и локального дневника на искусственных данных. Очки и координаты сверять с Android на тех же примерах, включая попадание на границе зоны. Отдельно проверить читаемость и жесты одной рукой. Результат испытания определяет, готовы ли расширять PWA до дневника.

На iPhone вход в тренировку после ручной блокировки подчиняется системной разблокировке. Офлайн-запуск зависит от подготовленного кэша, а сохранность данных сайта проверяется отдельно от кэша интерфейса. [Офлайн-ресурсы](https://web.dev/learn/pwa/assets-and-data) · [Хранение в WebKit](https://webkit.org/blog/14403/updates-to-storage-policy/)

## После проверки

[Подсчёт файлов, фактического времени и будущих затрат на обе версии](web-development-effort.md).

- Добавить историю, отчёт и перенос дневника через совместимый архив FableShot. Поддержку MyTargets включать после проверки совпадения очков и координат. Потребность в автоматической синхронизации уточнить отдельно.
- После успешной проверки переносить функции по одному рабочему сценарию. Общий экран и расчёты проверять в Safari и APK. Android-интеграции, включая экран блокировки, подключать отдельно. До смены основного APK проверить перенос дневника на копии и сохранение данных при обновлении.
- В комнатах проверять Android и iPhone вместе. Для подключения из Safari через точку доступа отдельно испытать реальное соединение без интернета. [Сценарий R1](../local-room.md)
- После перехода выпускать PWA и APK из одного проверенного коммита. Версию продукта задавать в одном месте. У APK дополнительно растёт номер сборки, который нужен для обновления Android.
