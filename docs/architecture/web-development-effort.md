# Сколько работы займут Android и веб FableShot

Срез на 11 ноября 2026 года. Цель веба — дать владельцу iPhone рабочую тренировку и дневник через Safari. Android остаётся текущим приложением для Xiaomi и realme. Обе версии используют одни правила стрельбы и один формат переноса дневника. [План первого прототипа](iphone-pwa.md)

Оценка сопровождения ниже относится к двум отдельным интерфейсам. В варианте с React и Capacitor общий экран реализуется один раз. Дополнительную работу по упаковке и проверке Android оценим по первому общему прототипу. [Схема переноса](iphone-pwa.md#как-организовать-перенос)

## Как вести разработку

Описываем изменение один раз. Например, «промах — это внесённая стрела с нулём очков». Берём один проверочный пример: 9 и промах дают 9/20. Проверяем этот пример в Android и в вебе. Если расчёт можно использовать в обеих версиях, исправляем его в одном месте. Если меняется кнопка или жест, проверяем экран на каждом телефоне отдельно.

Изменения для обеих версий делаем в одном пакете, когда соответствующая функция уже есть в обеих. Системные задачи Android, например поведение на экране блокировки, требуют только Android-проверки. Новые разделы веба добавляем по порядку использования. Сначала тренировка и сохранение, затем история и перенос. Так Android может получать обновления, пока веб догоняет по выбранным функциям.

## Что есть в проекте

Подсчитаны существующие отслеживаемые и новые неигнорируемые файлы до добавления этого отчёта. Кэш сборки, APK, локальные базы и резервные копии в подсчёт не входят. Для воспроизведения списка: `git -c core.quotePath=false ls-files --cached --others --exclude-standard`, затем удалить дубликаты и оставить существующие файлы. Категории определены по пути и по генераторам `scripts/extract-rank-catalog.py`, `scripts/prepare-fonts.py`.

- **535 файлов** в исходном списке. После исключения 17 схем Room, двух сгенерированных Kotlin-каталогов нормативов, пяти производных шрифтов и четырёх файлов Gradle Wrapper остаётся **507**. В эту цифру входят документация, ресурсы, тесты и служебные файлы.
- **168 рукописных Kotlin-файлов приложения.** Из 170 Kotlin-файлов продукта два генерируются из нормативной таблицы.
- **153 Kotlin-файла тестов** отдельно: 26 локальных и 127 Android. Проверочные сценарии полезны для веба. Android-тесты экранов останутся в Android, у веба будут свои проверки.

| Область рукописного кода | Файлов | Как используем для веба |
| --- | ---: | --- |
| Интерфейс | 77 | Пишем веб-экраны по мере включения функций. Сохраняем визуальные решения, названия и поведение. |
| Памятки | 5 | Переносим по отдельному сценарию, когда дойдём до этого раздела. |
| Расчёты и правила | 15 | Кандидаты на общий код. Сначала сверяем один расчёт и его тесты. Часть кода зависит от библиотек JVM. |
| Хранение, импорт, резервирование и экспорт | 65 | Разбираем по функциям. Формат данных и тестовые файлы переиспользуем. Для хранения в браузере и системных действий пишем свои части. |
| Связующий код приложения | 6 | Используем как описание переходов и состояний. Точка запуска и поведение платформы различаются. |
| **Всего** | **168** | Инвентарь существующего кода для оценки объёма. |

Для прототипа одной серии нужен **набор из 12 файлов-ориентиров**. Пять описывают экран, мишень, лупу, стрелы, сводку и тему. Три задают расчёт попадания и геометрию. Четыре показывают запуск тренировки и запись данных. Веб-реализация возьмёт нужные фрагменты поведения. Браузерное хранение и офлайн-запуск добавятся как новые части.

Ориентиры для реализации: `ui/{TargetBoard,TargetLens,ShotStrip,TrainingSummary,FableTheme}.kt`, `domain/{TargetScoring,TargetCatalog,ArrowShaft}.kt`, `MainActivity.kt`, `PracticeViewModel.kt`, `data/journal/{JournalPracticeStore,JournalDatabase}.kt` в `android/app/src/main/java/app/fableshot/android/`. Пять файлов интерфейса дают основу для новых веб-компонентов. Их количество может отличаться, потому что один веб-компонент может объединить несколько текущих частей.

Для близкого паритета есть 82 файла интерфейса и памяток, которые нужно рассматривать по сценариям, и 65 файлов хранения и интеграций. Количество новых веб-файлов станет известно после выбора состава версии и устройства кода. Размер отдельного файла также сильно различается, поэтому оценка времени ниже строится по законченным сценариям.

## Сколько уже заняло

По трём сегментам локального журнала этой темы с **29 октября 10:19 по 11 ноября 07:50**, время Новосибирска:

- **12 дней 21 час 30 минут** прошло по календарю.
- **Около 61 часа** заняли окна 149 завершённых и семи прерванных ходов вместе с ожиданием. Перекрывающиеся окна объединены. Среди них есть две паузы без событий примерно на 12 и 7,6 часа.
- **Около 39–41 часа по журналу активности.** Внутри ходов суммировались промежутки между событиями. При ограничении вклада одной паузы пятью минутами вышло 39,5 часа, при десяти минутах — 40,3 часа. Диапазон соответствует ограничению от трёх до пятнадцати минут.

Оценка включает чтение, разработку, обсуждения и ожидание инструментов в пределах выбранного порога. Шесть ходов без записи завершения исключены. Время параллельных подагентов не суммировалось. По этой истории нельзя измерить время Ивана на тренировки и ручные проверки или расход лимита Codex.

## Сколько планировать дальше

Это предварительная оценка рабочих часов для разработки, сборки и проверок. Ожидание доступа к телефону и ответы пользователя в прогноз не включены. После прогона на iPhone заменяем оценку прототипа фактом и пересматриваем следующие этапы.

| Этап | Часы | Результат |
| --- | ---: | --- |
| Прототип PWA | 6–10 | Одна мишень, лупа, зум и серия с сохранением. Повторное открытие с иконки без интернета на iPhone. |
| Основы дневника | +8–16 | Условия, история, правка попаданий, простой отчёт и восстановление незавершённой тренировки. |
| Импорт и перенос | +8–14 | MyTargets и перенос архива FableShot. Проверка чисел, координат и восстановления. |
| **Базовый веб-дневник, включая прототип** | **22–40** | Можно вести личные тренировки на iPhone и перенести дневник. |
| **Веб с большей частью нынешних возможностей Android** | **40–80 всего** | Расширенные отчёты, памятки, достижения, нормативы, постеры и проверки на телефонах. |

Совместная комната, автоматическая синхронизация между устройствами и функции, которых ещё нет в Android, оценены отдельно от этих диапазонов. Для них нужны собственные проверки и оценка.

Для поддержки после запуска удобна оценка на **10 часов обычного Android-пакета**. Если пакет меняет одну-две функции, которые есть и в вебе, закладываем ещё **3–5 часов на веб-адаптацию и 1–2 на проверку**. Получается **14–17 часов на обе версии**. При темпе 20 часов Android-работы в месяц это около 28–34 часов на обе версии при том же составе задач. У системной правки только для Android эта прибавка близка к нулю. Крупный экран, новый импорт или синхронизацию оцениваем отдельно.

Следующее решение принимаем по измерению первого прототипа. Нужны модель iPhone, удобство отметки у мишени и факт сохранения серии при повторном открытии без сети.
