# F03 — ядро дневника и перенос

29 октября 2026, ночная разработка. Пакет в работе; это не завершение F03/личной альфы.

## Реализовано

- JournalDatabase v2: Session → Block → End → Shot, отдельный счётчик без оценки, редакции и сохранённые квитанции операций. Экспорт схемы в Android app/schemas.
- Транзакционные старт/ввод/правка CAS/удаление с переиндексацией/серии/неполная серия/блок условий/разминка/завершение/пауза/корзина и восстановление. Повтор операции не дублирует выстрел и не воскрешает удалённый.
- MIGRATION_1_2 с проверкой исходных значений, точным переносом ID/очков/координат/времени/редакций и отказом для неизвестного профиля. Отсутствующие сведения не выдумываются.
- Граница PracticeStore и адаптер нового ядра для принятого редактора мишени. Экран условий, отдельный счётчик, выбор блока/разминки в S50 написаны и собираются; UI-проверки ещё выполняются.

## Каталог и интерфейс

Добавлен EquipmentDatabase v1 в отдельном `fableshot-equipment.db`: луки, стрелы, комплекты, архив, избранное, необязательные характеристики с единицами, редакции и история снимков. Это обратимое техническое разделение: Block хранит самостоятельный JSON-снимок выбранных объектов, межбазовых FK нет. Изменение/архивирование карточки не переписывает тренировку. Архивный связанный предмет скрывает комплект из нового выбора. Будущий архив приложения обязан включать обе базы и настройки.

После интеграции прошли **40/40 тестов, 26.189 s** (artifacts/verification/f03-regression.log): F02-регрессия 21, JournalShell 4, каталог 2, новое ядро 9, миграция 4. В частности, настоящий UI проводит правку/Undo, закрывает неполную серию, меняет условия без переписывания прошлого блока, отмечает разминку, завершает счётчик без фиктивных Shot, создаёт/выбирает/правит карточку без изменения снимка тренировки, обрабатывает ошибку чтения без ложного пустого дневника.

У заблокированного Xiaomi обычная тестовая Activity уходила в STOPPED, поэтому UI-прогоны останавливались до действий. Добавлена **debug-only VerificationActivity**, non-exported, showWhenLocked/turnScreenOn/keepScreenOn. Она показывает только собственные изолированные экраны поверх блокировки, не снимает её и отсутствует в release. Производственная MainActivity не меняет защиту телефона.
