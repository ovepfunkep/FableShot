# F01 — проверка сохранения и восстановления

29 октября 2026. Xiaomi 14, Android 16 / API 36. Основное приложение остаётся **0.1.2-dev**, Room schema **1**. Установлен только обновлённый служебный тестовый пакет; интерфейс/схема личного дневника не менялись.

## Изоляция

`RepositoryPersistenceTest` создаёт отдельную дисковую базу `fableshot-verification-<UUID>.db` для каждого теста и удаляет только её после проверки. MainActivity и репозиторий из FableShotApplication в этих тестах не открываются.

`ProcessPersistenceProbe` использует отдельную `fableshot-verification-process-v1.db` и собственный проверочный marker в SharedPreferences. До удаления имени проверяется префикс, запрещено имя `fableshot.db`. Никаких очисток данных приложения, личных тренировок или галереи.

## Сборка и шесть тестов репозитория

`assembleDebugAndroidTest testDebugUnitTest` — BUILD SUCCESSFUL. Новые тесты скомпилированы; существующие три теста геометрии — UP-TO-DATE (код геометрии не менялся, повторного доказательства здесь не заявляем).

На телефоне: `app.fableshot.android.RepositoryPersistenceTest` → **OK (6 tests)**, 1,181 с.

1. Повторное открытие дисковой БД сохраняет ID/условия/ревизии, центр (0,0), неизвестные координаты числового M, внешний M с точкой и ручные очки, отличные от автоматической зоны.
2. 24 конкурентных добавления в план 3 не переполняют серию; 12 повторов перехода создают ровно одну следующую. Пустая следующая серия не закрывается как полная; закрытая не принимает новые стрелы/правки.
3. Правка сохраняет ID, связь, индекс и время создания; возврат прежних значений повышает ревизию, а не откатывает её. Устаревший Undo вставки не удаляет более раннюю стрелу; следующая вставка после удаления последней корректно занимает свободную позицию.
4. Завершение серии с двумя внесёнными стрелами из шести сохраняет две, без четырёх дополнительных M; после открытия завершённая запись доступна.
5. Невалидные очки/непарные координаты отклоняются; ранее сохранённые данные остаются неизменными, дальнейший корректный ввод возможен.
6. Удаление одной тестовой Session каскадно удаляет только её дочерние записи; другая Session остаётся активной с прежними стрелами.

## Принудительное завершение процесса

Вызов класса `ProcessPersistenceProbe` с `probePhase=prepare` создал две тестовые серии. В первой сохранены 10 с координатой центра, 9 с последующей ручной правкой на 8 и M без координат; во второй — 7, серия осталась открытой.

После подтверждения commit тест отправил `PERSISTENCE_FIXTURE_READY pid=9343` и оставил соединение Room открытым. Затем отдельно выполнен `adb shell am force-stop app.fableshot.android.dev`.

Подготовительный runner сообщил **Process crashed** — это ожидаемая остановка для данного опыта, не успешно завершённый JUnit-тест подготовки. Он не включается в число пройденных тестов.

Повторный запуск с `probePhase=verify`: `PERSISTENCE_RESTORED writerPid=9343 readerPid=9553`, **OK (1 test)**, 0,083 с. Проверено, что PID другой; восстановлены Session ID, порядок/закрытость серий, очки `[10,8,0,7]`, ID/источник/ревизия ручной правки, null у числового M и известный центр. После проверки удалена только тестовая база и её marker.

Обычная MainActivity затем открыта: `Status: ok`, `LaunchState: COLD`. Личные записи не редактировались.

## Границы доказательства

Подтверждены нынешние операции репозитория и чтение после остановки процесса на отдельной базе. Это не проверка будущей миграции 1→2, не UI-прогон всей кнопки Undo, не тест отказа питания устройства/диска, не гарантия восстановления ещё не закоммиченного нажатия.

Текущий Undo — в памяти ViewModel; после перезапуска он не восстанавливается. Правка в нынешнем репозитории не имеет compare-and-set по ожидаемой ревизии; это требование нового контракта. Физическое удаление ещё не заменено корзиной. Эти ограничения не скрываются успешными тестами.

## Повторение

Запускать именно изолированный `RepositoryPersistenceTest`. Probe требует двух фаз: prepare → дождаться READY → force-stop в течение 30 секунд → verify. Не запускать бездумно весь androidTest-каталог: старые PersistenceSmokeTest предназначались для отдельного ручного сценария и используют рабочий репозиторий.
