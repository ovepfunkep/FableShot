# Первый сетевой прототип: точка доступа

**Решение пользователя:** начать совместный режим через точку доступа телефона. Это локальная сетевая комната; интернет-сервис остаётся резервом. Цель продукта до 50 стрелков сохраняется, но фактический предел одной точки доступа нужно измерить. Первое испытание — 2–3 телефона, затем 5/10 и дальнейшее увеличение до реально допустимого количества.

## Простой сценарий

1. Создатель включает обычную точку доступа Android в системных настройках и возвращается в FableShot. Автоматическое создание сети пока не требуется.
2. Приложение запускает локальную комнату на этом телефоне, показывает состояние сети, QR приглашения и инструкцию подключения.
3. Другие подключаются к Wi-Fi точки доступа, затем сканируют QR комнаты. Подключение к сети и вход в комнату — два шага; не обещать, что один QR автоматически выполнит оба на любом Android.
4. Участники вводят свои серии независимо, видят системы оценивания и срезы. Отсутствие интернета у Wi-Fi не означает отсутствие локальной комнаты.
5. Завершённые данные сохраняются на каждом телефоне. Серверное облачное хранение для этого прототипа не нужно.

Доступность интернета через раздачу не является условием работы комнаты. Требование — связь клиентов с локальным сервисом телефона. Проверить Android, который предлагает уйти с сети без интернета/использовать мобильную сеть: соединение приложения должно оставаться на выбранной локальной сети.

## Сетевой узел и равные права

Телефон создателя — **сетевой узел**, не спортивный администратор. Собственный ввод использует те же команды/проверки, что ввод остальных; нет права менять чужие стрелы, продвигать чужие серии, исключать завершивших участника из рейтинга или удалять чужую историю.

Локальный сервис хранит принятые редакции и выдаёт снимки/изменения. Стрелки сохраняют собственный первичный ввод и общие полученные результаты. Создатель не может незаметно менять общие формулы после начала.

Хранилище обслуживаемой комнаты отделено от личной истории телефона-узла. «Удалить у меня» скрывает/удаляет собственную запись и не стирает рабочие данные комнаты или опубликованные результаты остальных. Остановка сервиса/раздачи — другое явное действие с предупреждением об остановке обмена. Удаление приложения или отказ телефона физически может сделать узел недоступным; уже сохранённые на других телефонах снимки остаются у них.

Если сетевой телефон выключен, перегрелся, ушёл или остановил раздачу — обмен останавливается, личный ввод продолжается. Остальные не ожидают чужих серий, но для получения новых результатов нужен доступный сетевой узел. Восстановление исходного телефона/сети — первый путь восстановления. Бесшовная автоматическая миграция не обещана.

Предложение на будущее: явный перенос комнаты на другой телефон из подтверждённого снимка с новой эпохой узла/приглашением. Не объединять две независимые копии как будто это один сервер. Функция требует отдельной разработки и не блокирует простой первый прототип.

## Соединение и протокол

Проверяем локальный WebSocket либо эквивалентный упорядоченный канал; конкретная Android-библиотека выбирается на прототипе. QR содержит roomId, локальный адрес/порт, версию протокола и криптографически случайное приглашение. Адрес после изменения сети может измениться; новый QR нужен явно. Короткий код комнаты сам по себе не найдёт адрес без работающего обнаружения.

Защищённый канал с проверкой ключа/отпечатка из приглашения — целевой вариант. Пароль Wi-Fi не заменяет идентификацию комнаты. Секреты приглашений/участников не включаются в обычный экспорт. Нет административного секрета, общего для всех APK. Схема аутентификации, ограничение попыток и повторных пакетов проверяются до выпуска, не добавлением произвольного токена в открытый URL.

Повтор команд, revisions, outbox, подтверждение приёма и независимые серии описаны в [основной группе](group-session.md). Локальный узел подтверждает сохранение операции в устойчивом хранилище; получение сетевого пакета без сохранения ещё не гарантирует результат. Перезапуск восстанавливает ту же комнату из локальной базы, а не создаёт новую историю.

## Android и ограничения

Для первого варианта достаточно ручного включения системной точки доступа. Если позже делать создание сети из приложения, Android предоставляет [LocalOnlyHotspot](https://developer.android.com/develop/connectivity/wifi/localonlyhotspot): это сеть без интернета с отдельными требованиями разрешений. Не смешивать этот API с ручной раздачей в настройках телефона.

Учитывать [правила локальной сети Android](https://developer.android.com/privacy-and-security/local-network-permission): при target SDK 37+ на Android 17 прямой локальный обмен требует соответствующей реализации доступа; разрешения запрашиваются в контексте группы. Версию target и актуальные требования перепроверить перед кодированием.

Для узла проверить допустимый Android механизм работы при сворачивании/блокировке с видимым состоянием активной комнаты. Не считать бессрочный фоновый процесс гарантированным. Протестировать Xiaomi 14/HyperOS, энергосбережение, нагрев, питание, потерю сети, смену IP и возврат участников. Ненужное сканирование и обнаружение прекращать после входа/закрытия.

## Вместимость и запасной путь

Максимальное число Wi-Fi-клиентов и стабильность определяются телефоном, прошивкой и условиями. Раздающий телефон тоже стреляет локально; 50 стрелков могут требовать 49 внешних устройств плюс табло/зрителей. Это не подтверждённая вместимость Xiaomi 14.

Если один телефон не вмещает всех: сначала измерить предел и честно показать поддержанный размер для конкретного сценария. Для большого клуба остаются общий роутер с тем же локальным протоколом либо интернет-провайдер. Ветка бесплатно размещённой комнаты сохраняется в [исследовании расходов](brainstorm/10-group-costs.md). Не обещать объединить несколько точек доступа без маршрутизации или мостов.

Точка доступа не требует подписки на сервер. Она требует доступного телефона-узла и расходует его батарею. Возможные расходы на оборудование/мобильный тариф не выдаются за обязательную плату FableShot.

## Критерии первого прототипа

- 2–3 реальных Android без выхода в интернет: QR, вход, разные числа стрел, завершение собственных серий, одинаковый срез/зачёт.
- Создатель сворачивает приложение/блокирует телефон; фиксируется фактическое поведение узла и раздачи, а личные результаты не теряются.
- Потеря узла не блокирует ввод; после восстановления outbox сходится без дублей/потери правок.
- Подключение постороннего, чужая правка, повтор операции и устаревшая редакция обрабатываются по протоколу.
- Увеличение клиентов 5/10/далее, измерение подключений, задержек, нагрева/батареи и всплеска после серии. Отдельно проверяется реальная цель 50; при недостижении фиксируется предел и переход к резерву.

Это спецификация проверки, приложение и сетевой прототип пока не реализованы.
