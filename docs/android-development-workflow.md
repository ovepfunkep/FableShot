## Что можно брать на себя

- Вести исходники, интерфейс Compose, схему Room, миграции, CSV, CG3/PG1 и документацию по сохранённым спецификациям.
- Запускать сборки/проверки через инструменты проекта, читать ошибки и исправлять их. Android поддерживает сборку/установку через командную строку и Gradle Wrapper. Отдельно установленный глобальный Gradle не является обязательным: проект может использовать свой Wrapper. [Android: сборка из командной строки](https://developer.android.com/build/building-cmdline).
- После настройки запускать виртуальное устройство, устанавливать APK, открывать приложение, получать скриншоты/логи и выполнять поддерживаемые сценарии взаимодействия/автотестов. [Android Emulator](https://developer.android.com/studio/run/emulator-commandline), [ADB](https://developer.android.com/tools/adb).
- Подключать реальные разрешённые устройства к тому же циклу через ADB. Сам факт наличия чата на компьютере не даёт подключения к телефону: требуется настроенный и авторизованный канал.
- Выдавать проверяемый APK, журнал сделанного и сведения о том, где реально запускались тесты. Не считать отсутствие ошибок компиляции доказательством готовности всех функций.

Конкретные CLI/версии выбираются при настройке по текущим SDK/документации. Документация Android также описывает Android CLI; его наличие здесь не проверялось. Не полагаться на одну заранее угаданную команду или невидимую интеграцию IDE.

## Где участвует пользователь

При выборе проверки на Xiaomi: физически подключить телефон, включить отладку и подтвердить доверие к этому компьютеру на экране телефона. Если понадобится системный диалог вне доступной автоматизации, пройти его один раз; необходимость определяется реальной установкой, а не формальным запросом подтверждения каждой команды.

В дальнейшем пользователь проверяет то, что программные проверки не ощущают: удобно ли большим пальцем, видна ли лупа у реальной мишени, приятна ли вибрация, читаются ли подписи на улице. Сетевой режим проверяется на нескольких реальных телефонах. Один эмулятор не подтверждает работу точки доступа и целевую вместимость 50.

Сборки, повседневные исправления, анализ логов и повторные установки через уже разрешённое подключение берёт на себя агент. Для физического подключения телефона не требуется объявлять обязательный ручной труд на каждой версии.

## Маленький прогон перед большим приложением

1. Подготовить инструменты и зафиксировать пути/версии в инструкции проекта.
2. Создать минимальный проект с воспроизводимой сборкой debug APK.
3. Запустить на эмуляторе либо авторизованном физическом телефоне. Сохранить факт успешной установки и открытия, снимок экрана и логи запуска.
4. Добавить три попадания/простую локальную запись, закрыть/перезапустить приложение и проверить восстановление. Затем внести правку и проверить повторное сохранение.
5. Выполнить ещё одну небольшую правку интерфейса → сборку → установку → проверку. Этот шаг доказывает удобство всего цикла, а не только одноразовый запуск.
6. Продолжить вертикальными сценариями: лупа/масштаб, история/импорт, CG3/PG1 и отдельный сетевой прототип.

Критерий самостоятельного цикла: агент может повторять правка → сборка → установка → проверка → исправление, показывая реальные результаты. До прохождения прогона статус — «процесс спроектирован, среда не настроена».

## Phone Link и беспроводная отладка

Пользователь сообщил, что телефон уже связан с компьютером через Phone Link. Это не подтверждение ADB-соединения. Phone Link предоставляет пользовательские функции и на поддерживаемых устройствах вывод приложений/экрана; его можно сохранить как дополнительное средство просмотра. Полный цикл установки debug APK и получения логов требует отдельного канала разработки. [Microsoft: приложения через Phone Link](https://support.microsoft.com/en-us/windows/apps/mobileapps/use-apps-from-your-android-device-on-your-pc).

Кабель не обязателен: Android 11+ поддерживает беспроводную ADB-отладку с отдельным сопряжением по коду/QR. Нужны включённая беспроводная отладка, актуальные Platform Tools и доступная общая сеть компьютера и телефона. [Android: ADB по Wi-Fi](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi).

Следующее практическое уточнение — находятся ли компьютер и Xiaomi в одной доступной локальной сети/подключены ли к одному роутеру. При подходящей сети можно выбрать беспроводную отладку; USB остаётся простым резервом, если соединение блокируется сетью. Сопряжение Phone Link не отменять и не считать сопряжением ADB. Первое ADB-подключение впоследствии выполнено, подробности ниже; общий сборочный JDK/SDK по-прежнему требует подготовки.

Это не утверждение, что отладка уже доступна, и не разрешение на любые действия с личными данными телефона.

## Отдельная копия для ручной проверки

Для обновления APK запусти `./scripts/android-build.ps1`. Запрос `assembleDebug` или `assembleVerification` собирает оба варианта одним запуском. Скрипт проверяет одинаковые `versionName` и `versionCode` перед обновлением файлов.

- `artifacts/FableShot-debug.apk` — FableShot, пакет `app.fableshot.android.dev`.
- `artifacts/FableShot-test.apk` — FableShot Тест, пакет `app.fableshot.android.verification` с отдельным дневником.

Для каждой доработки готовить достаточно заполненных примеров в FableShot Тест, чтобы Иван мог проверить новый сценарий вручную. Использовать явно названные «Демо» записи, сохранять прежний тестовый дневник и повторно запускать наполнение безопасно. Текущие семь тренировок приходятся на разные даты за шесть недель, чтобы проверять фильтры истории и динамику. Источник примеров находится в `src/verification/java/app/fableshot/android/VerificationSamples.kt`. Тестовая Application добавляет текущий набор один раз. Отметка вне дневника предотвращает повторное наполнение после явного сброса. Основная Application не запускает этот сценарий.
