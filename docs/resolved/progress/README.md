# Прогресс — выбран PG1

29 октября 2026 пользователь поручил выбрать систему самостоятельно. **Решение проектирования: PG1 для Прогрессивного зачёта; PG2 только дополнительное объяснение.** Это выбранное правило первой реализации, а не предложение, ожидающее ответа. Правила Общих очков определены отдельно: [выбран CG3](../general-scoring/README.md). PG1 не меняется от этого выбора.

## Что означает результат

**P = 100 × (C − B) / H**, где C — текущий средний балл на стрелу, B — обычный средний, H — максимум одной стрелы по тому же профилю. Единица — **процентные пункты (п.п.)**, диапазон −100…+100. Символ H не смешивается с обозначением промаха M.

Пример при одинаковых 30 стрелах и максимуме 300:

- Обычно 50, сегодня 100 → **+16,67 п.п.**
- Обычно 100, сегодня 100 → **0 п.п.**
- Обычно 100, сегодня 110 → **+3,33 п.п.**

Средний балл исключает преимущество простого увеличения числа стрел: 50 за 10 стрел и 100 за 20 стрел означают одинаковый уровень и нулевой рост. Сильному стрелку труднее улучшить уже высокий результат; его мастерство отдельно видно в Классических/Общих очках. PG1 не объявляется официальным handicap или универсальной мерой навыка.

## База: последние похожие занятия

Выбрана политика **progress-pg1-v1**:

1. До начала текущего занятия отобрать завершённые прошлые занятия с той же дистанцией, профилем/версией зон, физическим размером и геометрией мишени, категорией лука. Неизвестные/неподтверждённые условия не считаются совпадением. Для многоточечного лица должен совпадать режим учёта лиц.
2. В каждом прошлом занятии требуется минимум **12 зачётных оценённых стрел в этих условиях**. Совместимые блоки одной тренировки объединяются в одну базовую запись; разные блоки не становятся несколькими тренировками. Разминка и счётчик без оценки не входят; M входит как 0, X — по правилам профиля.
3. Выбрать **до 5 последних подходящих занятий**. Для полноценного зачёта нужно минимум **3**. Базовый средний = сумма их очков / общее число оценённых стрел, без усреднения средних с одинаковым весом.
4. Конкретный экземпляр лука/комплект стрел и контекст тренировка/турнир показываются, но сами по себе не исключают иначе совпадающие условия в v1. Смена категории исключает. Дополнительные строгие фильтры доступны в исследовательском отчёте отдельно от зафиксированного зачёта.
5. Прошлое занятие должно быть завершено до начала текущего и присутствовать в истории на момент фиксации базы. Порядок — дата/время занятия; при совпадении времени стабильный ID. Нельзя выбирать только удачные/неудачные записи вручную для своего места в комнате. Удалённые записи не входят в новую базу; источник импорта виден.

Импорт MyTargets пригоден после проверки совпадения условий; координаты для зонального прогресса не обязательны. Неизвестный тип лука требует сопоставления, а не догадки по названию «My bow».

Параметры 5/3/12 выбраны как понятные начальные продуктовые значения, не как статистически доказанная гарантия. Испытания могут обосновать следующую версию политики; старые результаты не переписываются незаметно.

## Фиксация и нехватка данных

База замораживается до первой зачётной стрелы текущего занятия. Для нового блока условий снимок создаётся до его первой стрелы, но допускает только занятия, завершённые до начала всей текущей тренировки. Текущие/будущие стрелы, поздний импорт и чужая пятая серия не улучшают базу на третьей.

- Нет прошлых подходящих занятий — «Набираем базу · 0 из 3». Нет выдуманного B = 0.
- Есть 1–2 — допустимо предварительное сравнение с числом занятий и стрел, без полноценного места Прогрессивного зачёта.
- Есть минимум 3 — база готова. Настоящая база B = 0 допустима: PG1 вычисляется без деления на B.
- В текущем срезе менее **12 зачётных стрел в завершённых сериях** — живое сравнение предварительное. Полноценное место по накопленному прогрессу появляется после этого минимума при готовой базе. Неполная серия не даёт полного места за эту серию.

До накопления базы человек участвует в Классических и, при достаточных данных, Общих очках. Отсутствие прогрессивного места не является нулём, последним местом или наказанием новичку.

## Серия и накопленный результат

«За серию k» = PG1 по среднему завершённой серии k. Это отдельный краткий показатель, всегда с числом стрел; места по одной серии явно предварительные, поскольку один короткий эпизод изменчив.

«Итог до k» = PG1 по среднему всех зачётных стрел завершённых серий 1…k в том же зачёте. При пропуске серии полный срез отсутствует. Нельзя складывать проценты отдельных серий или включать данные после k. Для полноценного накопленного места действуют минимум 12 текущих стрел и готовая база. Срез на своей серии и ручной выбор номера сохраняются.

Разные условия получают отдельные сопоставимые подзачёты; приложение не усредняет их как единый достоверный рост. Смешанный общий список остаётся товарищеским с видимыми условиями.

Вычисления выполняются из исходных сумм/числа стрел без раннего округления. Показ — до двух знаков, без «−0,00». Для v1 место определяется числом в целых сотых п.п. после десятичного округления half-up; одинаковые показанные значения делят место 1,1,3. Сеть и скорость ввода не разрешают ничью.

## Дополнительные проценты и другие метрики

PG2 в подробностях: **100 × (C − B) / B**, только при B > 0, с подписью «Относительное изменение среднего». При B = 0 — абсолютная разница и PG1, без бесконечного процента. PG2 не влияет на место. PG3 не включён в первую реализацию.

Кучность, стабильность и смещение имеют собственные сравнения в [статистике тренировки](../../metrics-and-reports.md): например, RMS 40→34 мм означает улучшение кучности на 15%. Они не складываются скрыто в PG1. Прогресс Общих очков может стать отдельной будущей версией, при отдельном определении его версии и наличии совместимых исторических входных данных.

## История, интерфейс и события

Показывать PG1 в живой тренировке, итогах, истории, отдельной статистике, профиле и комнате; обычный прогресс не зависит от настроек достижений/анимаций. Подробности объясняют базу, даты/количество занятий и стрел, условия, формулу и предварительность.

BaselineSnapshot хранит policyId/version, список ID/редакций, суммы/число стрел, H, условия и момент фиксации. MetricValue/ScoreBreakdown ссылаются на этот снимок. Отчёт может показать отдельно новый исследовательский пересчёт, но не подменяет сохранённый результат комнаты. Исправления исходников видны; сам снимок не доказывает честность локальной истории.

Полноценный рекорд/достижение роста требует готовой базы, завершённого собственного зачёта и не менее 12 текущих стрел; конкретные дополнительные пороги события определяются в версии его правила. Малое предварительное отклонение не запускает полноценный рекордный праздник. Импорт/пересчёт не воспроизводят старые эффекты.

[История рассмотренных вариантов](11-progress-scoring.md). Повторно выбирать PG1/PG2/PG3 или подтверждать начальные параметры не требуется.
